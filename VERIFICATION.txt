Backrooms Infinity — verification notes for this archive

Changes in this revision
- Fixed the Godot/.NET SQLite runtime failure path that previously raised FileNotFoundException for Microsoft.Data.Sqlite 8.0.11.
- Backrooms.Infinity.csproj now sets EnableDynamicLoading=true and CopyLocalLockFileAssemblies=true so NuGet managed/native runtime dependencies are copied for Godot.
- LevelCatalogService still downloads levels.db.zip first, but if SQLite runtime dependencies cannot be loaded it automatically uses the mirrored raw GitHub data/catalog.json; cached and bundled JSON fallbacks are also supported.
- SQLite parsing was isolated in SqliteCatalogReader so a missing SQLite assembly does not prevent the rest of the catalog service from loading.
- XML script language is now explicit and mandatory: type="lua" or type="gdscript".
- Existing 50 bundled levels were migrated to type="lua".
- Runtime GDScript support was added through Godot.GDScript SourceCode -> Reload() -> New() -> run(ctx).
- Lua remains the preferred content scripting language. GDScript has a documented context bridge for diagnostics, generation, world, UI and shader controls.
- Added docs/GDSCRIPT_API.md and updated level-format/Lua/debugger/architecture documentation.
- CI now checks that Microsoft.Data.Sqlite, SQLite native runtime, and MoonSharp runtime files are present after Debug build.

Checks performed in this environment
- tools/validate_repo.py: PASS
- All Level-0..49 ZIP files opened and passed CRC validation through the repository validator.
- All 50 level.xml files parse as XML and every <script> has a valid explicit type. Existing sources are .lua and use type="lua".
- levels.db.zip parses with Python sqlite3; schema remains download_link, preview, name; 50 rows match data/catalog.json.
- GitHub Actions YAML parses with PyYAML.
- Backrooms.Infinity.csproj parses as XML.
- Final project ZIP integrity is checked after packaging.

Environment limitation
This sandbox does not contain the .NET SDK or the Godot .NET editor binary, so a real dotnet build / Godot runtime launch cannot be executed locally here. The repository CI performs those real build/import/startup checks on GitHub Actions. The source changes were therefore additionally guarded by repository validation and CI runtime-dependency assertions.
